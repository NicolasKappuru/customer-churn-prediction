Guía de src/w3_reinforcement_leraning/environment/env.py
==========================================================

Este archivo define TelcoRetentionEnv, el entorno de Gymnasium para probar
estrategias de retención de clientes. No implementa DQN: el entorno describe
el problema y una política (por ahora, random_policy.py) decide qué acción
intentar.

¿Qué pide Gymnasium y qué es auxiliar?
--------------------------------------

Gymnasium necesita que el entorno declare action_space y observation_space,
y que implemente reset(), step() y render(). Esos son los métodos públicos
principales que utilizará una política o un algoritmo de RL.

Los demás métodos de TelcoRetentionEnv son auxiliares propios del proyecto.
Separan tareas para que reset() y step() no tengan que contener toda la lógica
de preprocesamiento, predicción, restricciones y transformación del cliente.
No son requisitos adicionales de Gymnasium.

Flujo de una ejecución
----------------------

1. Se crea TelcoRetentionEnv(). Su constructor prepara el preprocesador,
   selecciona los clientes disponibles y declara los espacios.
2. reset() elige un cliente (o el indicado por options["customer_index"]),
   obtiene la probabilidad inicial de churn y entrega su observación.
3. La política consulta la máscara de acciones y elige una estrategia válida.
4. step(action) sortea si el cliente acepta la oferta.
5. Si acepta, se modifica una copia de sus datos y el modelo calcula churn de
   nuevo. El entorno calcula la recompensa y termina el episodio.
6. Si rechaza, conserva el cliente y la probabilidad original, da reward 0 y
   también termina el episodio. Cada episodio representa una sola oferta.

Componentes del módulo
----------------------

RetentionAction
    Estructura inmutable con el nombre de una acción, su probabilidad de
    aceptación y su costo. Los costos de descuento se expresan como fracciones:
    0.05, 0.10 y 0.15; no como números 5, 10 y 15.

ACTION_DEFINITIONS
    Catálogo de las 15 acciones. La posición de cada una es su identificador
    discreto para Gymnasium: por ejemplo, action=0 es contrato de un año y
    action=14 es Streaming Movies. El mismo identificador se usa al validar,
    aplicar y contabilizar una acción.

RAW_FEATURES / CATEGORICAL_FEATURES / CONTINUOUS_FEATURES
    Describen los campos crudos que forman el estado y cuáles son categóricos
    o numéricos. RAW_FEATURES contiene 19 características. CustomerID se
    excluye completamente porque solo identifica al cliente. Churn también se
    excluye porque es la etiqueta histórica, no un dato que la política use
    para decidir.

ENGINEERED_FEATURES / OBSERVATION_FEATURES
    Las características derivadas son NewCustomer y AvgMonthlyCharges.
    La observación contiene solo los 19 campos crudos, esas dos características
    y la probabilidad de churn: 22 números normalizados entre 0 y 1. No contiene
    CustomerID ni un índice de fila.

SERVICE_PRICES
    Precios mensuales aproximados sumados a MonthlyCharges cuando se agrega
    un servicio. No son el costo de descuento usado directamente en la
    recompensa: representan el precio del servicio en el registro del cliente.

INTERNET_DEPENDENT_SERVICES
    Lista de complementos que requieren servicio de internet y que se utiliza
    tanto al validar como al aplicar ofertas de servicios.

Métodos de TelcoRetentionEnv
----------------------------

__init__(dataset_path=None, render_mode=None)
    Configura el entorno. Carga TelcoPreprocessor y los registros utilizables,
    define action_space=Discrete(15) y observation_space=Box(0, 1, shape=(22,)).
    También obtiene categorías y rangos para escalar las observaciones y
    prepara las variables que representan el episodio actual.

_find_positive_class_index()
    Averigua qué columna de predict_proba representa la clase 1 (churn). No
    asume que esa columna siempre ocupa una posición fija.

_predict_churn_probability(customer)
    Envía un cliente crudo al preprocesador y al modelo supervisado. Devuelve
    la probabilidad de churn, comprobando que esté entre 0 y 1.

_get_action_mask(customer)
    Genera un vector de 15 ceros y unos: 1 significa que esa acción se puede
    ofrecer al cliente; 0 significa que no. Evita, entre otros casos, ofrecer
    Phone Service a quien ya lo tiene, Multiple Lines sin Phone Service, o
    complementos de internet cuando no hay internet o el complemento ya existe.

action_masks()
    Expone la máscara del estado actual para que una política compatible pueda
    consultarla. Gymnasium básico no la aplica automáticamente: la política
    random del proyecto escoge entre las acciones con máscara 1. Si se pasa
    directamente a step() una acción que la máscara prohíbe, el episodio
    termina sin cambio y con recompensa cero.

_observation()
    Construye el vector que observa el agente. Normaliza campos categóricos,
    valores numéricos y características derivadas, y añade la probabilidad de
    churn actual. No cambia los datos del cliente.

reset(seed=None, options=None)
    Inicia un episodio según la API de Gymnasium. Selecciona un cliente al azar
    (reproducible usando seed), salvo que se dé customer_index en options.
    Calcula el churn inicial y devuelve (observation, info). info incluye el
    churn inicial y la máscara de acciones. customer_index puede darse como
    opción para seleccionar una fila en pruebas, pero no se incluye en el
    estado ni en la información devuelta.

_apply_action(customer, action)
    Aplica a una copia del cliente el cambio de contrato, descuento o servicio.
    No decide si la oferta se acepta, no calcula la probabilidad de churn y no
    calcula reward; esas decisiones pertenecen a step().

step(action)
    Avanza el MDP. Primero comprueba que el episodio esté activo y que action
    pertenezca al espacio. Después verifica la máscara y sortea la aceptación.
    Si la oferta válida se acepta, modifica el cliente, calcula churn nuevo y
    recompensa:

        reward = 100 * (churn_antes - churn_despues - costo)

    Todas las cantidades dentro del paréntesis son fracciones. Por ejemplo,
    churn_antes=0.77, churn_despues=0.60 y costo=0.15 producen reward=2.
    Si el cliente rechaza, reward=0. Devuelve el contrato Gymnasium:
    (observation, reward, terminated, truncated, info). Este MDP es de un paso,
    así que terminated=True al procesar la oferta y truncated=False.

render()
    Muestra el contrato, el cargo mensual, la probabilidad de churn y la
    cantidad de acciones válidas. No muestra identificadores de cliente. En modo human imprime el texto;
    en modo ansi devuelve una cadena. Sirve para depuración, no para entrenar.

Ejemplo mínimo de uso
---------------------

    from w3_reinforcement_leraning.environment.env import TelcoRetentionEnv

    env = TelcoRetentionEnv(render_mode="ansi")
    observation, info = env.reset(seed=42)
    valid_actions = [i for i, allowed in enumerate(info["action_mask"]) if allowed]
    action = valid_actions[0]
    next_observation, reward, terminated, truncated, info = env.step(action)
    print(env.render())
    env.close()

El índice de acción que utiliza el agente siempre debe seleccionarse entre los
valores permitidos por action_mask. La observación siempre tiene 22 valores:
19 características, 2 variables derivadas y la probabilidad de churn.
CustomerID no se utiliza en el preprocesamiento, la observación ni el modelo;
action_mask e info son datos auxiliares, no componentes del vector de estado.
